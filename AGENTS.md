# Repository Guidelines

## Project Overview
Kanon is a pure-Rust Native Shell app for Windows and macOS only, with no bundled JS VM. Follow [GLOSSARY.md](GLOSSARY.md) for Knowledge Base, Document, Project, and Task terminology.

## Architecture & Data Flow

- `nsh.json` → `"rust": "."` + `"root": "App"` binds the crate and root component. No TSX entry exists; `nsh run` runs the Rust root.
- `src/lib.rs` → `#[native_module("kanon/native")]` (must stay at lib.rs root, exactly one per crate) registers `App` for export; add more exports via `registry.register::<T>()` (components), `registry.module::<M>()`, `registry.class::<C>()`. `#[component] pub fn App()` is the root — `Root::of::<App>()` requires `Props: Default`, so keep root props absent or defaultable.
- `.nsh/` → generated by the `nsh` CLI (`rust/` runner crates, `types/` declarations, `tsconfig.json`). **Never edit; gitignored.** Runner crates path-depend on this repo by absolute path — moving/renaming the repo requires regenerating `.nsh/`.

**Core reactivity rule: a component body runs once; only bindings re-run.** A value read in the body is a snapshot. Pass `move ||` closures (or signals) to setters for anything that must stay current:

```rust
let count = signal(0_u32);
view()
    .child(text(move || format!("Count: {}", count.get())))   // binding: re-runs on change
    .child(view().on_press(move || count.update(|v| *v += 1))) // handler: writes signal
```

## Key Directories

| Path | Purpose |
|---|---|
| `src/lib.rs` | `mod` lines, `#[native_module]`, the `App` root (reads `AppProps`: workspace path + optional fixed clock) |
| `src/main.rs` | Desktop launcher; passes `AppProps::desktop()` (file workspace, system clock) |
| `src/domain/` | Pure-Rust domain: `workspace.rs` (SQLite facade + business rules), `date.rs`/`clock.rs` (floating local time), `schema.rs`, `task.rs`; zero UI-crate deps |
| `src/ui/` | Styled control layer above `nsh-base`: `theme.rs` (semantic tokens + motion from `theme.json`), `controls.rs` (buttons, inputs, task circle, panels) |
| `src/shell/` | Workbench shell: `store.rs` (reactive store over `Workspace`), `tabs.rs` (routes/history rules), `topbar.rs`, `sidebar.rs`, `context.rs`, `task_detail.rs` |
| `src/today/` | The Today view (date strip, carryover, quick add, task list) |
| `theme.json` | Semantic color/radius tokens (docs/ui-design.md §5), light + dark |
| `.nsh/` | Generated: `.nsh/rust/` per-platform runner crates + workspace, `.nsh/types/` TS declarations (incl. `kanon/native.d.ts` from `#[native_module]`) |
| `target/` | Cargo build output |

## Development Commands

| Command | Does |
|---|---|
| `nsh check` | `cargo check` on the crate, then type-checks `*.test.tsx` |
| `nsh test` | `cargo test`, then every `*.test.tsx` headless |
| `nsh run` | Run on this machine's Windows or macOS backend |
| `nsh test nsh.json --trace` | Headless: what the root mounts + time per commit |
| `nsh package --target windows` | Package on Windows; use `--target macos` on macOS |
| `cargo check --all-targets` | Fastest edit loop for pure-Rust changes |
| `cargo run` | Direct native desktop run via `src/main.rs` (Win32 or AppKit) |
| `nsh test --target macos` | Run `*.test.tsx` on a real platform |

Typical loop: `nsh check` → `nsh test` → `nsh run` to see the UI. Rust edits under `nsh run` rebuild and restart; there is no hot reload for Rust.

## Code Conventions & Common Patterns

- Edition **2024** (Rust ≥ 1.85); `use nsh_core::prelude::*;` + `use nsh_base::theme;` at top of UI files. Builder methods (`Styled`, `Interactive`, `Accessible`, `ParentElement`) come from the prelude.
- Components: `#[component] pub fn Name() -> impl IntoElement`, PascalCase names, constructed by snake_case fns (`stepper()` → `Stepper`). Plain functions returning `impl IntoElement` are the default for UI pieces; `#[component]` only when it needs its own owner/events/TSX export.
- Signals are `Copy` — capture freely in `move` closures. `.get()` inside a binding subscribes; in a body/listener it is a snapshot (use `.get_untracked()` there anyway). `.set()` skips equal values; `.update()` always notifies.
- Conditional/list content is a region, not `.child(closure)`: `when(cond, a).otherwise(b)`, `each(items, key_fn, row_fn)`, `dynamic(..)`, `virtual_list` for unbounded lists. `.style_when(cond, |s| ..)` for state-driven styles.
- Styling is typed builder methods on the Tailwind 4pt scale: `.flex_1()`, `.gap_4()`, `.px_5()`, `.py_3()`, `.rounded(px(10.0))`, `.text_size(px(28.0))`.
- **Colors only via theme tokens**: `.bg(move || theme().primary)`, `.text_color(move || theme().foreground)`. Never `rgb(..)` in app code. Wrap `theme().*` in `move ||` so theme changes propagate.
- Native state styles cost nothing: `.active(|s| s.opacity(0.6))`, `.hover(..)`, `.focus_visible(..)`. Never hold hover/press in a signal.
- Root fills the surface: `.flex_1()` + `theme().background`; `.p_safe_area()` on content.
- Growing the app (per NSH conventions): keep `lib.rs` to `mod` lines + `#[native_module]` + root; put styled controls in `src/ui/` (`theme.rs`, `controls.rs`) before writing screens; one module per feature (`notes/`, `projects/`, `tasks/` — a big feature becomes a directory with its store in `mod.rs`); keep domain logic (note model, project/task state, persistence) in plain Rust types that compile and test without the engine.

## Runtime/Tooling Preferences

- Use the NSH CLI version pinned in `Cargo.toml`. TypeScript is only used for `*.test.tsx`; keep the application itself in Rust.
- Standard cargo applies (`cargo fmt`/`clippy` usable but unconfigured). README optionally recommends the `huacnlee/cargo` fork.
- Don't edit or commit `.nsh/` or `target/` (both gitignored); regenerate via `nsh check`/`build`.

## Testing & QA

- Test framework: `nsh/test` — `import { expect, open, test } from "nsh/test"`. `open(".")` starts the Rust root (relative to the test file) on a headless engine.
- Driver: `app.press(sel)`, `app.texts()`, `app.type(sel, text)`, `app.waitFor(sel)`, `app.back()`; `open` options: `platform`, `width`/`height`, `colorScheme`, `storage`, `network`, `clock`.
- Selectors: bare string resolves test-id → label → text; prefixes `id:`, `label:`, `text:`, `role:`, `view:`; `a >> b` nesting; `nth=N`.
- Existing coverage: one test asserting `Count: 0` → `Count: 2` after two presses.
- For new Rust-side UI tests, use `nsh-engine` and `nsh-testing` at the app's NSH version (`default-features = false`). Start `Headless` with `EngineConfig::new(Root::of::<nsh_app_kanon::App>())` and drive it with semantic selectors.
- Headless proves behavior, not appearance — visuals need `app.screenshot(path)` under `nsh test --target <graphical>` or a manual `nsh run`, checked in light + dark.
- New behavior should come with a `*.test.tsx` (or `Headless`) test; name tests for behavior (`counts_taps`), one flow per test.

## Agent Working Conventions

### Language

- Git commit messages: **English**.
- This file (`AGENTS.md`): **English**.
- Documents under `docs/`: **Simplified Chinese** (commands, paths, code, config keys, API and error messages stay verbatim).
- GitHub issues and PRs — title, body, review comments: **English**.

### Git & PR workflow

- Large or long-running features developed on parallel branches land on the default branch via GitHub PRs, one PR per feature branch.
- Merge PRs with **Squash and merge** only — keeps a linear commit graph; never create merge-commit bubbles.

### Build & test hygiene

- Fix every error and warning from `cargo check`/`nsh check`, `nsh build`, clippy, or the test runner as soon as it appears — **never commit code that still emits warnings**.
- `nsh build` findings (undocumented exports, unknown classes, unused declarations) count as warnings.
