# 文档严格单归属于知识库，项目通过关联而非独立容器挂载文档树

Kanon 同时提供语雀式「知识库」与「项目」两类核心容器。我们决定所有 `Document` 严格单归属于唯一 `Knowledge Base`，`Project` 不持有独立的文档存储容器，而是关联一个知识库或其中的目录分组（创建项目时支持一键新建同名知识库）。

## Considered Options

- **项目独立持有文档树**：文档分裂为「知识库文档」与「项目文档」两套容器，导致跨项目沉淀、全局目录管理与项目归档迁移成本上升。
- **仅靠标签松散关联**：无法在项目视图内提供语雀式的结构化书目与多级目录树体验。

## Consequences

- 不存在孤儿文档；项目完成或归档后，沉淀的文档完整保留在知识库中且路径与链接不变。
- 项目视图内的「文档」子页直接复用知识库目录树与文档阅读/编辑组件，避免维护两套文档管理 UI。
