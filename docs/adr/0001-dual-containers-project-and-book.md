# 顶层容器采用 Project 与 Book 双轨模型

Kanon 需要同时承担“以个人项目推进为主轴”和“替代语雀进行长期知识沉淀”两类职责。我们决定废除 Woday 语义模糊的扁平 `Folder`，在顶层并列提供带生命周期状态、目标及任务视图的 `Project`（个人项目）与无期限的 `Book`（长期知识库），两者内部均采用语雀式的层级目录树（`Catalog`）组织 `Document`，并支持项目完结后将高价值 `Document` 迁入 `Book` 沉淀。这样既避免了像语雀一样缺乏原生项目推进容器，又避免了将无截止日期的通用知识（如语言笔记、读书笔记）强行塞入短期项目。
